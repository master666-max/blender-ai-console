## 一、这是什么

**Blender AI 建模控制台**：让 LLM 通过 MCP 驱动 Blender 做 Geometry Nodes 建模——
AI 写 **plan-JSON（不是代码）** → 编译器产出 GN 节点组 → opinion 层 → 三层回退 →
verifier 门禁 → 段落边界渲染 diff + spec 级 A/B。

**主体性声明（M8 反转兑现）**：本项目主体是 `blender_console/`（30+ 模块：
FlowDAG/WAL、编译器、verifier、A/B 协议、经验库、导演会话）；
`brickfly_mcp` fork 仅是**传输壳**（上游 Brickfly MCP + 11 个 gn 工具薄封装）。

## 三、安装与起桥（三步）

1. **装 whl**（或直接用随包 `.venv-mcp`）：
   `pip install m8_bridge/brickfly_mcp-2.1.0-gn-py3-none-any.whl`
2. **MCP 客户端配置**（WorkBuddy `mcp.json` 实配，server 名 `blender-gn`）：
   ```json
   {
     "command": "<bridge>/.venv-mcp/Scripts/python.exe",
     "args": ["-c", "from brickfly_mcp.server import main; main()"],
     "env": { "BLENDER_MCP_SAFE_MODE": "1" },
     "timeout": 30000
   }
   ```
   装好后需在客户端连接器管理页 **Trust 激活**。
3. **起桥**（Blender 侧，TCP 9876）：双击 `m8_bridge/start_gn_bridge.bat`
   ——已内置 `GN_ALLOW_BACKGROUND=1`（fork 放行后台起服的开关，漏设会导致
   server.start() 静默 return、端口不监听）。保持窗口开着，然后客户端即可调用。

⚠ `SAFE_MODE=1` 时 AI 侧只发 plan-JSON（工具面不走 execute_code 代码通道）。

## 七、R6 过程留痕（两处实锤教训）

1. **手工起桥漏 `GN_ALLOW_BACKGROUND=1`** → 上游守卫静默 return、端口不监听，
   冒烟/e2e 全挂；bat 分发物已内置该变量，手工起桥必须带上。
2. **plan_schema.py 主线↔部署漂移**：R5 的 M9-1b 修复改了主线但漏同步 gn_deploy
   （R5 同步清单漏项）——R6 diff 校验抓出，cp 后零漂移，冒烟复跑 16/16 确认。
   教训固化：**diff 校验必须是机械步骤，不能靠清单记忆**（本仓库 `_build_release.py`
   已把零漂移作为 manifest 前置硬校验）。
