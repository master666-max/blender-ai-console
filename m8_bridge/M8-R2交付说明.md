## 一、R2a 沙箱白名单实测（未核实点 → 已核实，19/19 与预期一致）

用上游原版 `safe_mode.is_safe`（逐文件加载，未改一行）实测 19 个代码模式：

| 模式 | 结果 | 结论 |
|---|---|---|
| `import json/math`（白名单） | 过 | 对照组 ✓ |
| `import mug_compiler`（部署模块） | **拦** | Tier-1 import 桩在 SAFE_MODE=1 下死路 |
| `import sys/os/pathlib/hashlib` | 拦 | 我们的依赖全部不在白名单 |
| `class` 定义 / `contextlib` | 拦 | console 结构代码无法过闸 |
| **预注入 globals 名字调用**（Tier-1.5） | **拦**（unknown name） | 名字解析被 AST 静态检查 |
| **`bpy.app.driver_namespace` 字典注入**（Tier-1.5 最终形态尝试） | **拦**（上游显式黑名单："injects globals into driver expression eval"） | 连这个口子都封了 |
| `__import__`/`globals()` 逃逸 | 拦 | 判别力验证 ✓ |

**结论**：SAFE_MODE=1 下 Tier-1/Tier-1.5 **全部封死**（上游沙箱 deny-by-default 且覆盖
到字典注入）；SAFE_MODE=0 下桩可行但放弃防护。**R2b 工具化是唯一同时满足安全与
能力的路径**——handler 是插件自有代码，不经沙箱，且 R12 语境下 AI 只发 plan-JSON。

另两个事实：①沙箱默认**关闭**（opt-in），v1 报告的"安全模式拒绝"是开启态现象；
②`execute_code` 的 exec 环境**只预注入 `{"bpy": bpy}`**。
