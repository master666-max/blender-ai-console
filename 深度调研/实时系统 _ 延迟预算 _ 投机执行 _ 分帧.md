【实时系统/延迟预算/投机执行/分帧 深度调研报告】

一、机制/技术（6条）
1. 投机执行 + 误预测补偿 — Microsoft Outatime/DeLorean（OSDI'14/微软研究院）：云端游戏延迟 250ms 内被完全掩盖。核心手法：并行投机求值多个可能未来帧 + checkpoint/rollback 防错误传播 + 误预测后用图像变换做轻量补偿而非重算。映射：AI 流式生成 plan 的 1-3 秒，正是投机窗口；我们 0.19ms 的 checkpoint 快照就是现成的 rollback 基础设施。
2. Any-time 分帧绘制 — H3Viewer guaranteed frame rate（Stanford，Munzner）：绘制循环按投影面积排序逐个画，帧时间预算耗尽立即终止（active 模式保证响应），停止交互后用多个 bounded idle 帧逐级补全画面。这是"预算到就停、结果分级补全"的经典模式。
3. Time-critical LOD — Funkhouser《Adaptive Display Algorithm》：按帧率硬预算自适应选 LOD，超时降细节而非超时。CAD 侧先例：Meshmatic 给每个网格生成 5 级 LOD、中望 CAD 用"动态像素剔除"在拖拽时轻量化显示。
4. 管线分段延迟预算 — NVIDIA Reflex：把 input→simulation→render submit→driver→render queue→GPU 每段插桩计量，"just-in-time"对齐各段消除排队。官方观点：延迟在管线里守恒，"一处减掉会在另一处加回来"，不全链路计时等于盲优化。
5. 缓存调度系统 — Disney《Achieving Real-Time Playback with Production Rigs》（SIGGRAPH 2015）：RigCache 最小化 scene graph 重复求值 + Parade 分布式调度缓存更新，"只算一次、多处复用、由调度器预热"。
6. Blender 官方缓存/裁剪设施：GN Bake 节点（4.x）可把树中任意中间几何 bake 到内存/磁盘，Simulation Zone 播放时自动缓存；视口 Render Region（Ctrl+B）只算矩形区域内像素——但仅 Cycles 视口支持，EEVEE 不支持。

二、设计转译（段落边界 100ms 总预算）
1. 编译 10ms：AI plan 流式输出时边解析边编译（plan 通常 1-3s 生成完，编译早就该完成），段落边界只做校验。
2. GN 求值 0-40ms：投机求值——AI 生成期间后台线程对上一版 plan 的邻近参数（最可能的 A/B 变体，2-3 个）并行求值。Outatime 的经验是状态空间要"子采样"：只投机参数的 ±1 档，不做全排列。
3. verifier 10ms + 超时降级：超时改抽样验证（红绿判定只查改动影响的子图）。
4. 渲染 20ms 两级：先低 LOD + Render Region/裁剪出 diff 预览（<10ms），高 LOD 异步算完原子替换（学习 H3Viewer active/idle 两阶段）。
5. GN 40-60ms 求值不能分帧：depsgraph 刷新是同步 work_and_wait，策略应是"后台线程整体求值 + 视口双缓冲显示旧版本 + 求值完 swap"，而非切成 <16ms 片段。
6. 预热缓存：在 GN tree 的高成本上游节点插入 Bake 节点（still 模式），AI plan 解析出"可能被改的参数"后提前预 bake 变体——对应 Disney RigCache 的"调度器预热缓存"思想。

三、反直觉/打脸（4条）
1. Blender depsgraph 的"异步求值"从未落地：官方 wiki 有 Deferred Updates For Depsgraph 设计提案（后台线程求值慢节点），2.8+ 的多线程只是"图内独立分支并行"，单个 GN 修改器仍是同步阻塞黑盒。指望升级 Blender 获得分帧求值会打脸。
2. EEVEE 不支持视口 Render Region（仅 Cycles 视口支持）——如果 diff 渲染走 EEVEE，增量裁剪要自己用 scissor 实现，别假设原生免费。
3. 投机的浪费率极高（Outatime 带宽 1.9-4.5 倍、 ghost 计算率 50%+），但对 40ms 级、空闲核上跑的任务，浪费 CPU 不等于浪费延迟——该投就投，只需给投机线程设核数上限。
4. Reflex 的管线守恒律：我们目前 verifier 和渲染 diff 没计时，意味着 100ms 预算里可能有 30-50ms 在看不见的地方流失——先插桩再优化，顺序反了全白干。

四、可直接抄的策略（5条）
1. 段落等待期=投机窗口：AI 生成期间预求 2-3 个邻近参数变体，用户选 A/B 时命中则 0 延迟；误选则用 0.19ms checkpoint 回滚重算（误预测补偿用旧图+局部重算，不整树重跑）。
2. 双缓冲 swap 替代分帧：旧结果持续显示，后台整树求完原子替换，视口永不阻塞。
3. 两级渲染契约：低 LOD/低采样 + 区域裁剪 <10ms 先出，高 LOD 异步补全（Cycles adaptive sampling 天然渐进）。
4. 全链路分段计时器（仿 Reflex latency metrics）：编译/GN求值/verifier/渲染各设预算与超时降级表，每段独立可关。
5. GN tree 内插 Bake 节点做预热缓存锚点，AI plan 附带"参数热度表"驱动预 bake 顺序。
