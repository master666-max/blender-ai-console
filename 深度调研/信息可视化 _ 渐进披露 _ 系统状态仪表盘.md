【d3-infovis 调研报告：信息可视化 / 渐进披露 / 状态仪表盘】

■ 一、研究/设计系统结论（已核实）→ 页面映射

1. Shneiderman 视觉搜索三段式（"The Eyes Have It", 1996, doi:10.1109/VL.1996.545307）：overview first → zoom & filter → details on demand。实例化为仪表盘三层 IA：顶层只放"监控分诊"所需（KPI 大数字 + 异常旗标），中层按需展开分析，底层放决策/细节（timgraf.com 的认知负荷分层框架）。映射：M9-4b 页面纵向就是这三层，当前把 DAG 全量铺开违反第一层原则。
2. Tableau 官方眼动研究（tableau.com 博客）：用户看 dashboard 跟看网页一样走 F 型；"大数字"比任何图表元素快约 1 秒抓住首次注视；重复排列的元素注意力从左到右急剧衰减（一排 5 个 KPI 卡，后 2 个几乎无人看）；页面顶部注视时长最长。→ 回答了"用户最常看什么"：左上角的大数字和顶部区域。
3. 布局算法决策树（skillmd.ai 汇总 + Svelte Flow 官方布局指南）：流程图/工作流/DAG 用 dagre（≤500 节点）或 ELK layered（复杂 DAG、端口约束、≤1000）；力导向只适合无向/环状网络，流程轴上会变 hairball。两者都是确定性布局，利于空间记忆。
4. 语义缩放（semantic zoom）研究（ZMLT/GraphMaps 一系 + acejournal 2026 综述）：节点 3→300 靠"换表示"而不是"几何缩放"；粗层要 aggressively 剪边，聚合成带计数的 supernode；关键警示——多数用户读不懂无提示的聚合节点（supernoding 需配计数徽标）；层间切换要保持空间稳定。
5. NHS Scotland Turas 状态调色板（设计系统）：RAG 状态必须"颜色+形状+文字"三通道；红绿同用对 ~8% 男性不可分；文字标签永远可见、不许只藏在 tooltip。CSS 层面有 oklch 安全色板（teal 代替纯绿，h195/h50/h25/h265 四色相）。
6. NN/g 折叠面板研究（Accordions on Desktop）：桌面端折叠只在"用户只需访问少数几节"时使用；嵌套折叠是明确反模式；最大坑是缺少"可展开"的 signifier。GOV.UK 风格的原生 <details>/<summary> 是单文件零 JS 的标准答案。

■ 二、设计转译（具体到 M9-4b 区域）

1. 顶部新增 KPI 带：左上放 3 个大数字卡——override 率 / dirty 步数 / verifier 未通过数，不放迷你图（大数字本身吸引力最强）。按眼动数据每行最多 3-4 个，最重要的放最左。
2. 流程轴 DAG 区域改为横向分层布局（rank 左→右）：单文件下不必引 dagre，按拓扑 rank 分列 + flex 列排即可得到同样的确定性布局；边用 SVG path，同列节点对齐。
3. 20+ 步段落改三级语义缩放：段落卡（默认，只显示首尾节点+"12 步"计数徽标）→ 阶段条（点击展开，每段 5-8 步一组）→ 单步节点（再点一层）。每级聚合节点必须带计数徽标（ZMLT 教训：裸 supernode 没人看得懂）。展开时保持已见节点位置不动（空间稳定）。
4. 四状态编码分通道：verifier 用形状（✓/✕/…前缀符号），override 用位置（节点左侧 3px 色条），dirty 用边框样式（虚线边框），revision 用角标数字。颜色只做辅助通道且避免红绿对：用 teal(通过)/orange(警告)/blue(信息) oklch 同亮度组。状态文字永远可见。
5. 假设面板 / GoodPoint 详情改原生 <details>/<summary>，::marker 换成 CSS 自定义箭头补 signifier；不嵌套，一段一折叠。
6. 暗色模式：全部颜色收进 :root CSS 变量 + @media (prefers-color-scheme: dark) 一处覆盖；背景 #121212 系（禁纯黑），主文字 ~87% 白，accent 去饱和提亮；加 data-theme 手动开关 + localStorage（几行 JS，主题值在 head 渲染前应用防闪白）。

■ 三、反直觉/打脸

1. 力导向布局对流程轴是错误答案——研究共识：流程/管线类必须用分层布局，力导向只会产生 hairball 且布局不确定。
2. 折叠不是渐进披露的万能钥匙：NN/g 明确折叠会降低内容发现率，"用户需要看全部内容时应该全部平铺"。20 步的段落该折，但 KPI 和异常旗标永远可见。
3. 顶部 KPI 卡别放 5-6 个——眼动数据显示第 4 个以后注意力断崖式下跌，排得越多等于把重要指标亲手埋掉。
4. 我们可能低估"大数字"：Tableau 实验里大数字的首次注视比图表快整整 1 秒——状态页应该以数字为主视觉，图形为辅。

■ 四、可直接抄的 CSS/交互模式

1. 主题：:root 定义 --bg/--surface/--text/--border/--status-* 令牌，@media (prefers-color-scheme: dark) { :root {…} } 一处覆盖；手动切换用 html[data-theme] 选择器 + localStorage，JS 判断放在 <head> 里防 FOUC。
2. 状态徽标：.badge--ok::before{content:"✓ "} .badge--warn::before{content:"⚠ "} .badge--err::before{content:"✕ "}，配 oklch(0.52 0.16 195) 等 4 安全色相令牌（WCAG 1.4.1：颜色不许是唯一通道）。
3. 原生折叠：<details><summary>步数徽标 + 标题</summary>…</details>，summary 上加箭头旋转动画（details[open] summary::marker / 自定义 span transform）。
4. override 色条：.node{border-left:3px solid transparent} .node--override{border-left-color:var(--status-orange)}——不占额外空间、位置语义稳定。
5. 三级展开的最轻实现：每级内容预先渲染成 hidden div，点击只切 class，不做动态插桩；聚合计数徽标 <span class="count">12 步</span>。
