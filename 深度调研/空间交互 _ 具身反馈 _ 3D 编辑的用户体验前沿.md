【d2-spatial 调研报告：空间交互 / 具身反馈 / 3D 编辑 UX 前沿】

一、研究/交互模型（均已 WebSearch 核实）
1. Lasso 系 3D 选择（TeddySelection/CloudLasso, IEEE TVCG 2012；Tangible Brush, CGF 2019）：用户在屏幕画 2D 套索，系统沿视线挤出成 3D 选区体积，自动按密度定界——无需多步布尔操作。启示：我们的"区域反查"不需要用户在 3D 里精确框选，2D 屏幕套索 + 深度自动解析就够。
2. 可提示分割（SAM 3, Meta 2025；SAMPart3D 2024 / P3-SAM 2025）：文本短语（"那个把手"）或单击点即可分割 mesh 的语义部件，P3-SAM 原生支持 3D 部件分割。这与 AZURITE"区域→段落"反查是天作之合：点击/文本先过分割模型，分割出的面片集合再反查覆盖它的段落。
3. 沉浸分析综述（Fonnet & Prié, IEEE TVCG 2021）：指出 VR 审查领域"多感官通道被严重欠利用"、3DUI 成熟知识未迁移——意味着我们的触觉/声音提案正好踩在领域空白上。
4. VR 比较任务的系统评估（CHI 2025, "Assessing Visualization and Interaction Techniques to Support Comparison Tasks in VR"）：VR 中并排不可行（一次只能占据一个 3D 空间），时间位移式切换 + 局部区域控制胜出。
5. 视觉比较三分类（Gleicher et al. 经典 taxonomy）：juxtaposition（并排）/ superposition（叠加）/ explicit encoding（显式差异编码），是所有 A/B 呈现研究的公共框架。
6. 简短音频警报元分析（Nees & Liebman 2023, 系统综述+元分析）：speech/spearcons > auditory icons > earcons；earcons 在准确率、反应时、主观评分全面垫底。

二、设计转译（段落边界交互升级）
1. 段落→可点选区域：渲染图上用户框选/套索区域 → P3-SAM/SAM 类模型分割出面片组 → 反查覆盖该面片组的 Thought 段落，对话自动注入"你选中的是第 N 段产物"。这是 AZURITE 反查的最短 UI 路径。
2. A/B diff 从并排改为"对齐叠放 + 闪烁"：Hild et al. 2018 实证：对齐位置的交替闪烁呈现，命中率、完成时间、 workload 均优于并排（自动化 change mask 叠加后命中率可达 95%）。我们的两版渲染图本就同机位同构图，闪烁条件天然满足。
3. 增加"滑块擦拭"模式作补充：CHI 2026 沉浸视频比较研究（N=20）显示 sliding 混合式最受偏好（40% 首选票），适合逐区域精看；闪烁适合扫差异，滑块适合看细节。
4. verifier 结果接声音通道：异常=不协和低音蜂鸣、正常=静默（Amer et al. 2013 证实不协和/低音 earcon 能传达"严重度"梯度）；但按 Nees 元分析，若要传达具体错误类型，压缩语音（spearcons）比抽象蜂鸣有效得多——"非流形边"播语音比播哔声好。
5. 触觉通道（远期）：Scene2Hap（CHI 2026 最佳论文）证明 LLM 可自动生成物体级振动反馈；桌面端可降级为"鼠标悬停到有非流形边的区域时手柄/触控板短促粗糙振动"。属加分项而非主线。
6. 手势映射（存疑，见打脸第 2 条）：Quest 捏合=选择、捏合拖动=平移是成熟范式，但"捏合=合并两段、张开=拆段"这类抽象段落操作没有文献支持，风险高。

三、反直觉/打脸
1.  earcons（抽象蜂鸣）是被元分析打脸的经典方案——直觉上"正常=无声、异常=哔"很合理，但数据显示抽象音效的识别准确率和主观评分垫底；语音提示反而最好。想加声音通道就别只做哔哔声。
2. 手追踪精度不足以支撑精细编辑：Quest 2 实测指尖位置误差 1.1cm、关节角误差 9.6°、延迟 45ms（Abdlkarim et al., Behavior Research Methods 2023）。做"合并/拆段"这种需要选到具体段落锚点的操作会频繁误触。手势只适合粗粒度确认/取消，不适合定位。
3. VR 审查并非全面更优：VR 比较研究中并排在 VR 里反而不可行；VR 的优势在具身性带来的理解深度（VR'26 回放研究显示任务理解显著更好），代价是设备、 Comfort、交互学习成本。对"改一句话"级别的反馈，桌面仍是性价比之王。
4. Blender 5.0 已把 GreasePencil 更名为 Annotation、API 重构——社区教程里大量旧 API 代码会直接失效，集成时要按 5.0 的 bpy.types.Annotation 写。

四、Blender 生态内可用（无需自写引擎）
1. Grease Pencil/Annotation 标注即数据：bpy.ops.gpencil.annotate() 产生结构化 stroke（点坐标+压力+strength），可程序化读取；stroke 支持 SCREEN/2DIMAGE 显示模式，正好用于"在渲染图上画→读坐标→反投影定位几何区域"。这就是"区域反查"的最自然 UI，且零新依赖。
2. 选择状态全可编程：bmesh 的 verts/edges/faces 有 .select 属性，bpy.ops.mesh.region_to_loop()/loop_to_region() 可做区域↔边界环互转——AI 反查到段落对应的面片后，可直接在视口高亮 outline 给用户看"这段就是这些面"。
3. select_mode（VERT/EDGE/FACE）+ select_flush_mode 支持混合模式选择，段落边界（通常是一条边环）可以用 edge 选择模式精确可视化。
4. 闪烁 diff 不需要插件：同机位渲两帧，用 Blender 自带 image editor 的 flipbook 式切换或 Compositor 做叠加差异图（explicit encoding）即可，成本极低。
5. VR 审查可借 Blender 内置 VR addon（OpenXR）或导出 glTF 进现成 viewer，不必自研；但优先级应低于标注反查路线。

【核心结论】优先级排序：① Grease Pencil 标注→分割→段落反查（零依赖、最自然）② 闪烁式 A/B diff（有实证支持、实现极简）③ spearcons 语音化 verifier 结果（替代蜂鸣直觉方案）④ VR/触觉/手势均为远期加分项，当前投入性价比低。
