【可逆计算 / 可逆编程语言 / 补偿事务调研报告】

一、里程碑成果
1. Bennett 1973《Logical Reversibility of Computation》(IBM J. R&D)：任意计算都可逆化——保留全部中间状态（历史带），正向算完→拷出结果→逐步 uncompute。代价：朴素实现空间 O(T)；用 pebble game 分块可换到 O(S·log T) 空间 / O(T·log²T) 时间。这是"重算当撤销"的理论原型，正对应你们"意图层重推下游"。
2. Janus（Lutz & Derby 1982，Caltech；Yokoyama & Glück PEPM 2007 形式化 + 求逆器 + 可逆自解释器）：首个可逆结构化命令式语言。保证：程序求逆是**机械的局部变换**——if 需双条件（if e1 then s1 else s2 fi e2，回退时 test/assertion 互换）、from-until 循环需入口/出口断言、赋值限为 LHS 不出现在 RHS 的 reversible update。证明"我们无法在 Janus 里写出不可逆程序"。关联：可逆不是"每条命令手写 undo"，而是**语法结构强制**、逆自动导出。
3. Landauer 1961 + Bérut et al. 2012 实验：擦 1 bit ≥ kT·ln2。要区分**逻辑可逆**（状态映射是双射，纯软件概念）与**能量可逆**（绝热硬件恢复能量，~1/T 下降）。软件架构只需前者；Theseus（James & Sabry 2014，Indiana）那类"每步都是 iso 的纯函数式语言"是逻辑可逆的极致形态，无真实工业应用（未核实到任何）。
4. Saga（Garcia-Molina & Salem 1987, SIGMOD）：补偿是**语义冲正而非逆函数**——论文自己的座位例子：补偿是"取消该预订"而非"把计数器改回 1"，因为并发事务可能已改动状态。补偿不可擦除"已被观察"这一事实、必须幂等、必须留审计痕迹。原文模型不带隔离性：观察过中间结果的外部事务不会被自动通知。
5. RCCS（Danos & Krivine 2004）一系可逆进程代数：核心结论是**因果一致性**——并发回退不该按全序栈回滚，而按因果等价类"先撤果、后撤因"；后续 roll-π 把事务解释为 ballistic process，commit 即执行不可逆动作。判定问题：弱可观察等价在 rhoπ 中已证不可判定（Lanese 等）。
6. Sparcl（Matsuda & Wang, ICFP 2020）：高阶部分可逆语言，用线性类型+pin 算子分离可逆/不可逆部分。理论结论：**不存在"所有函数箭头都是双射"的高阶可逆语言**——高阶可逆性必然引入部分可逆。

二、可直接抄的已解决问题
1. 「每条 Command 自带 undo()」应升级为「Command 空间结构化到可机械求逆」：参数更新类命令携带 (node, param, old, new) 即天然自带逆（O(1)）；拓扑增删是互逆对；参照 Janus 禁止"黑盒语句"进入状态层。
2. 表达式求值不可逆不损害命令可逆——Janus 的 reversible update 已证明：把不可逆部分（求值）隔离在只读侧，写侧保持单射。对应你们：AI 计划编译（不可逆）与 modifier 参数写入（可逆）分离即可。
3. 回退方向用 Saga 词汇明确分类：每个命令标 compensable / pivot / retriable。外部副作用（渲染导出、落盘）是 pivot，跨过 pivot 只许 forward recovery。
4. 补偿留痕：undo 不做破坏性擦除，日志追加冲正记录（Saga 审计要求），这样语义层 GoodPoint 校验可审计。

三、坑 / 反直觉发现
1. 「任意程序自动求逆」被数学封死一半：非单射函数根本没有唯一逆；剩下一半被复杂度封死——基于搜索的符号求逆（如逻辑式求逆）理论上能逆但逆程序可能指数慢（Matsuda ESOP 2010 明确此分类问题）。工程可行前沿只有：限定语言子类（Janus/RFun）+ 求逆器，或 Sparcl 式部分可逆。没有任何语言做到"任意程序自动求逆"（此结论由多源交叉确认）。
2. Java/C++/Rust undo 框架的共同死穴不是实现偷懒，而是三件形式化必然：(a) 非单射操作信息已丢，逆需 ancilla（Bennett 的 garbage bit）；(b) 中间状态被外部观察后补偿失效（Saga）；(c) 并发下"逆序回放"≠"回到过去"（RCCS 因果序 vs 全序栈）。Command vs Memento 两难只是这些死穴的工程投影。
3. 反直觉：纯"从日志重放/重算"并不总是更便宜。Bennett pebble game 证明纯重算的空间/时间代价可能超线性，所以才需要 checkpoint 层——对应你们三层架构里"状态层快照"不是历史包袱，而是复杂度保险，别为了压成本砍掉。
4. memento 全量快照对"百万顶点 3D 场景"内存爆炸是实测公认的（Photoshop/Premiere 类软件的 undo 栈均设上限+脏矩形缓存），delta 快照实现极易出错。

四、对本项目的具体建议
(a) undo() 与"从日志重放"**形式上不等价**。undo()=补偿（语义冲正，在当前态上运行，要求命令与补偿可交换/幂等）；重放=forward recovery（要求确定性执行+全部输入可复现）。两者等价仅当：所有操作单射、无并发干扰、执行确定。代价：undo() 每命令 O(1) 撤销但逆可能写错；重放存储 O(日志) 但天然支持"改参数重推"。**建议两者都要，分层负责**：意图层（改参数重推下游）用重放——Blender 依赖图本身就是 Bennett uncompute 机，重算成本接近零，符合北极星；状态层（拓扑编辑）用自带逆的 Command；快照做兜底。要求"每条 Command 自带 undo()"作为接口契约，但逆操作由命令构造器从 (old,new) 参数**机械生成**而非手写——这是从 Janus 学到的把正确性从约定变成结构。
(b) 自动求逆已被理论封死到只剩一条路：**把命令 DSL 设计成 Janus 式受限语法，使"可逆"成为类型/结构性质**。任何超出该语法的操作（第三方插件直改 mesh）拒绝进入回退体系，只许走快照层。不存在中间道路。
