【算法学 × 增量/缓存/指纹 — 深度报告】

## 一、硬结论（4-6 条）

1. **"改一个参数必须重算的最低代价"没有普适下界，且部分问题类无界**。Ramalingam (1993) 以 ‖δ‖（输入+输出的变化量）为参数建立了增量复杂度层级：最短路有 O(‖δ‖log‖δ‖) 的 bounded 算法；但**电路值问题（circuit value problem）增量复杂度为 Ω(2^‖δ‖)**（有匹配的指数下界）；图可达性、数据流分析在稀疏别名指针机模型下是 **unbounded**——不存在只依赖 ‖δ‖ 的更新算法。任意计算图（含 Blender GN 树）最坏情形下单参数修改可强制全树重算，这是问题属性而非实现缺陷。

2. **speedup 大小由算法的 stability 决定，不是由增量框架决定**。Acar 体系的核心量是 trace stability：change propagation 代价 = 传播距离 × O(1) 依赖跟踪常数（Acar 2005 博士论文证明 DDG 跟踪开销 O(1)）。但 TOPLAS 2009 实验分析明确指出："渐近加速是罕见的（rare）：对许多计算和修改，change propagation 不比从头重算快"。分离结论：归并排序插入元素可得 O(log n) 重算，而稳定性差的算法 speedup≈O(1)。你们的 1.02-1.10 正是"DDG 常数因子开销 + 浅 DAG 值稳定"叠加的结果。

3. **demand-driven（Adapton, PLDI'14）是重算量的正交削减**：demanded computation graph 保证只有 observer 实际需要的输出才传播失效——重算量上界从"受影响子图"降到"受影响且被需要子图"，实测在多数基准上显著优于 type-directed 自调整计算。这是 Salsa/下代引擎的语义基础。

4. **并行自调整计算已有关联 work/span 理论界**（Anderson-Blelloch-Baweja-Acar, SPAA'21）：用 SP-tree 跟踪顺序/并行控制依赖，界以计算"距离"参数化——若你们要并行化红绿传播，这是唯一直接可引的理论。

5. **CDC 对顶点流的适用边界**：FastCDC（Gear hash，每字节 O(1)，归一化掩码）吞吐约 10× Rabin，插入/删除只影响当前及下一块。但**移位韧性只对"字节相同、位置移动"有效；数值微变会破坏所有后续块边界**。几何"移动无关指纹"的正确组合 = 量化浮点 → Morton 码空间排序 → CDC；严格的 order-invariant 摘要只能靠可交换聚合（逐块哈希的 XOR/加法多重集摘要，64-bit 碰撞 2^-64），但它丢弃顺序信息，只能做等价初筛。

6. **感知哈希的实测分离度**：pHash 在 Hamming ≤2 时 FPR≈0.1%，放宽到 ≤14 时飙至 ~73%（ImageNet 规模基准）；渲染回归实践数据：同源重编码距离 0-2，主体替换 18-30——存在清晰阈值带，但**pHash 会漏按钮变色、单字符排版变化**；SSIM 会把窗口内局部变化平均掉（单像素边框 1→2 漏检）。LPIPS 在渲染回归上的假阳/假阴率【未核实】。GGPO 侧没有形式化的内存-时间权衡分析【未核实】，只有工程准则：rollback 可行域 = 小状态+快模拟+2 玩家；RTS 尺度（MB 级状态）重放 10 帧超实时，出现螺旋死亡。

## 二、设计转译（4-6 条）

1. **VersionedParams 保留量化浮点，但失效语义升级为 Adapton 式 DCG**：dirty 传播加两个停止条件——(a) 值传播而非拓扑传播（重算后值相等即停，Salsa 的"equal 试探"有理论依据：TOPLAS 2009 指出值稳定性检查是加速来源）；(b) 只对被 observer 需要的节点传播。红绿双色 + 这两条，预期把 1.02-1.10 的比值中"无效重算"部分压掉，但不要指望 <1.0（DDG 边跟踪的 O(1) 常数是地板）。

2. **输出指纹具体参数**：64-bit Gear hash，min=256B / avg=1KB / max=8KB（顶点量化至 12B 后约 85 顶点/块），归一化两段掩码（2/1 分段）。流程：quantize → Morton 排序 → FastCDC → 逐块 xxh64 → 可交换聚合（加法模 2^64）得 order-invariant 摘要。几何等价判定：摘要相等 ⇒ 视为同几何；不等 ⇒ 按块 diff 定位差异区域。

3. **checkpoint 缓存别用 LRU，也别迷信 ARC**：libCacheSim 多尺寸实测 ClockPro 命中率超过 ARC/LRU/S3-FIFO；现代 SOTA 是 S3-FIFO/Sieve（FIFO 变体，15-20M req/s，接近 Belady）。锚点负载是"新版本流式追加 + 随机历史读"= 扫描+混合型，天然 anti-LRU。建议：单线程选 ARC（自适应 p 对混合负载最好），多线程选 S3-FIFO 或 ClockPro（锁开销远低于 ARC）。

4. **GGPO 权衡译到 Blender**：快照内存 ≈ S×k，重放时间 ≈ k×T_step。GGPO 能纯输入重放是因为状态小且 T_step 小；GN 修饰器状态 MB 级、重放慢，所以"每 N 步全量快照 + WAL 重放补间"是正确混合，N* ≈ S_serialize / T_step 的实测交叉点。快照内容纪律照抄 GGPO：只存影响未来仿真的状态（RNG 状态、量化后几何），排除 cosmetic 缓存，实体按稳定 ID 规范排序。

5. **RevisionTable 写成 30 行 TLA+ spec**：不变量三条——哈希链单调（每事件 prev 指向后继哈希）、revision 单调、dirty 传播的不动点语义（无新增 dirty 时收敛）。用 TLC 模型检查 compaction 与失效的交错；参照 Depot 实践：1,429 万状态/21 分钟/验证 10 条安全不变量是常规规模。未发现现成的 "event sourcing 哈希链" TLA+ 模型库【未核实】，需自写。

## 三、反直觉/打脸（3 条）

1. **1.02-1.10 不是"还没做优化"，可能是地板**：电路值问题的指数下界 + unbounded 问题类的存在说明，modifier 层红绿判定只能改善平均情形与常数，某些参数（如影响全局拓扑的）理论上就必须全树重算。给产品定 KPI 时不要承诺最坏情形。

2. **CDC 直接用在原始顶点流上是错的**：浮点重排或末位抖动会摧毁所有块边界。必须先量化+空间排序，否则块复用率归零——这不是工程细节，是 CDC 移位韧性定义使然。

3. **pHash/SSIM 都不能单独当"视觉等价"判据**：pHash 是预过滤器不是比较器（会漏颜色/文字级回归），SSIM 会平均掉局部变化。可靠方案是级联：pHash 预筛（距离 <3 判不变）→ 逐像素/pixelmatch 兜底。"固定视角+已知光源"确实是最稳配置，但稳的是逐像素法，不是哈希法。

## 四、立刻可做的实验（3 个）

1. **顶点指纹 A/B**：同一 GN 树改 1 参数，对比 (a) 原始 float 流 CDC / (b) 量化+Morton 排序 CDC / (c) 全量重算。判定：方案 (b) 块复用率 ≥80% 且指纹计算耗时 < 重算耗时 5%，才接入主链路；否则退回几何量指纹。
2. **感知哈希分离度**：固定视角渲染 100 对图（50 真无变化、50 真实回归），画 pHash 汉明距离与 SSIM 双分布。判定：若 pHash 距离同源 ≤2 且回归 ≥8（无重叠带），启用预筛级联；分布重叠则放弃 pHash。
3. **快照 vs 重放交叉点**：对最贵 modifier 实测 T_step 与状态序列化时间 S，k=1..10 扫描"每帧快照"vs"1 快照+k 重放"。判定：交叉点 k*<3 用纯快照；k*>10 用混合（每 k* 步快照 + WAL 补间）。
