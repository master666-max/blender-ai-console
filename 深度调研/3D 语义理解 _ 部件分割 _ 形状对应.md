【d4-semantic 调研报告】3D 语义理解 / 部件分割 / 形状对应（深度版）

## 一、研究/算法清单（5 条核心 + 2 条相关）

1. **PartNet / PartNet-E 数据集**
PartNet（CVPR 2019）：573,585 个部件实例、26,671 个 3D 模型、24 个物体类别，三级粒度标注（level-3 细到 "椅子背上的竖杆"）。PartNet-E（PartSLIP 团队构建，CVPR 2023）：取 PartNet-Mobility + PartNet 合并，测试集 1,906 个形状、45 类、约 103~106 个部件（含 wheel/handle/knob 等机器人友好部件）。是部件分割的标准 benchmark。与我们的关系：评测任何"用户说把手→定位面片"方案的地板基准。

2. **PartSLIP（CVPR 2023）**：用 GLIP（图像-语言预训练）做 2D 检测再投影到点云，low-shot 部件分割。零样本 PartNetE 语义 mIoU **27.3%**（45 类平均，见 PartDistill 论文 Table 2）。开源（GitHub col14m/PartSLIP）。启示：纯零样本部件分割天花板很低，**远不够产品级定位精度**。

3. **SAMPart3D（arXiv 2411.07184，2024）**：当前零样本部件分割最强。不依赖文本提示，DINOv2→PTv3 蒸馏 3D 特征，多粒度分割 + VLM 打标签。PartObjaverse-Tiny：语义 mIoU **34.7%**（PartSLIP 24.3）；类无关分割 **53.7%**（SAM3D 43.6）；实例分割 mAP50 30.2。开源（GitHub Pointcept/SAMPart3D）。关键点：它输出的是"多粒度部件实例"，语义标签由 VLM 后挂——意味着**分割可靠、命名模糊**，与"用户说'把手'"之间仍有 gap。

4. **SAM 3D（Meta，2025-11）**：注意区分——论文 Table 里的 "SAM3D" 是早期分割模型；Meta 2025 年 11 月发布的 SAM 3D Objects 是**单图→3D 生成**基础模型（代码权重开源 github.com/facebookresearch/sam-3d-objects），配套 SAM 3 支持文本提示分割（LVIS AP 48.5）。对我们的价值不在分割，而在"从照片生成带语义 mask 的 3D 资产"管线入口。

5. **Functional Maps 形状对应**：Ovsjanikov et al. 2012 经典框架，在函数空间求低维矩阵映射，再转点对点对应。经典应用清单里**明确包含 segmentation label transfer**——正是我们要的"把旧 mesh 的 Thought 标签传输到新 mesh"。最新进展：ReMatching（ECCV 2024）通过低分辨率重网格把 functional maps 扩展到百万顶点 mesh；2024 年有中文综述《泛函映射及其在非刚性三维形状对应领域应用综述》。开源生态：pyFM、potpourri3d。

6.（相关）**MeshSegmenter（ECCV 2024）**：零样本 mesh 语义分割，靠生成纹理合成提升 2D 分割在"几何不显著区域"（如车门）的精度——直接对标我们的"杯子把手"场景。**3-By-2（ECCV 2024）**：training-free，用 2D 语义对应在 PartNetE 上零样本 SOTA。

7.（相关，最重要的一条）**CAD/CAE 的 Virtual Topology 管线**：Lecallard et al., "Propagating Design Updates to Structured Analysis Meshes"（Computer-Aided Design, 2022）。做法：把参数化设计更新**增量传播**到已分解的网格与拓扑——改了哪里、只重建哪里的面片集，其余 cell 的归属映射原样保留。CADOps-Net（2022）甚至直接把面片分割与"设计历史（construction steps）"关联。**这说明我们"编译器天然知道段落归属"的优势在 CAE 工业界已被利用，但在 AIGC/Blender 生态是空白。**

## 二、关键设计转译：编译时打 named attribute（我们的独有优势）

Blender 设施已完全够用（已核实官方文档）：GN 有 **Store Named Attribute** 节点（支持 Face 域、Integer 类型、Selection 输入），**Named Attribute** 节点读取，Shader 的 Attribute 节点也能读，且 named attribute 随几何数据持久存在、可随 USD/Alembic/FBX 导出。

具体实现方案：
① 标签编码：每个 Thought 段落分配稳定整数 `thought_id`；在 mesh 上存 **两个 face 域 named attribute**：`wbp_thought_id`（int, Face）和 `wbp_part_name`（string 不支持，可用 vector/color 编码或存 object custom property 的 id→名字字典——custom property 存映射表，attribute 存逐面 id，这是标准做法）。
② 编译器注入：GN 编译器在**每个段落子图的输出端**自动插入一个 Set/Store Named Attribute 节点，Selection=该段落子图的几何，Value=常量 thought_id。多段落汇合后天然形成逐面标签场，**零推理、100% 准确**。
③ 读取路径：用户说"把手太粗"→ LLM 从 Thought 树拿到"把手"的 thought_id → 一个临时 GN modifier（Named Attribute 节点 + Equal 比较 + Delete/Separate）即可选中/高亮/统计该面片集；或 Python 侧直接读 attribute 数组做面片筛选。
④ 回写路径：Set Named Attribute 也能让"用户选中面片→反查归属段落"闭环，供对话上下文使用。

## 三、用户手改后标签怎么维护（段落→面片集映射）

面片索引在手改（细分/删除/雕刻）后必然漂移，与 TNP 同构。三层防线：

1. **第一层：Blender 自身的传播**。named attribute 会被 GN 节点自动插值传播（细分时子面继承父面标签，已核实 attribute 会随几何操作传播），且 Blender mesh 有内置 `id` 属性可作稳定锚点（其在面域的持久性**【未核实】**）。Subdivide/Smooth 等常规操作下标签基本自动存活——我们只需把"标签丢失检测"挂在 depsgraph 更新回调上。
2. **第二层：增量修复（对标 CAD virtual topology）**。diff 手改前后的拓扑：未变区域（按邻接+几何指纹匹配）标签直接沿用；新增面片用"父面重心归属"（细分）或 KNN/最短路径边界扩展（雕刻）传播。只更新受影响 island，成本 O(改动量)。
3. **第三层：兜底重分割 + functional maps 标签迁移**。拓扑变化过大时，跑 SAMPart3D 重分割（无需文本提示，恰好适配），然后用 functional maps 把旧 thought 标签场作为函数传输到新分割上（这是 fmaps 的教科书应用），VLM/LLM 校验部件名一致性。触发阈值：标签丢失面片占比 > 15% 时。

几何指纹方案：对每个标签 island 存（面积、质心、法向直方图、面积加权 shape diameter）哈希，手改后用指纹重锚定 island，避免全量 fmap 计算。

**一句话结论**：零样本 AI 部件分割（SAMPart3D 53.7% 类无关 mIoU）只配做兜底；我们的胜负手是编译时 Set Named Attribute 注入逐面 thought_id（Blender 设施现成、零成本、100% 准确），配 CAD 式增量修复 + functional maps 标签迁移兜底手改场景。此"编译即分割"路线在 Blender/AIGC 生态无人做过，是可写的差异化点。
