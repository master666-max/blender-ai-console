# [第 1 路] 自调整计算 / 增量计算（self-adjusting computation & incremental）

- 调研代理：general-purpose-7 ｜ 回报 2026-09-27 00:40
- 定位：这是"局部重算"的正规理论，直击我们最痛的「GN 无局部重算」

## 一、里程碑成果
1. **Self-Adjusting Computation**（Umut Acar，CMU 博士论文 CMU-CS-05-129，2005）：程序运行时自动构建动态依赖图（DDG），输入变更后由 change propagation 只重放受影响的子计算；依赖追踪开销 O(1)，trace stability 分析证明多个应用（凸包/排序/树收缩）的更新复杂度接近专用动态算法最优界。
2. **一致性语义**（Acar/Blume/Donham，ESOP 2007）：change propagation + memoization 组合的形式语义，用 Twelf 机器证明 from-scratch 一致性 → 保证增量结果 = 全量重跑结果，回退层可放心用。
3. **Adapton**（Hammer 等，PLDI 2014）：改为需求驱动（demand-driven）的 Demanded Computation Graph，只有被 demand 的计算才传播变更；Rust 实现避免 GC 拖累 → "按需失效"优于"急切传播"。
4. **Incremental Computation with Names**（Hammer 等，OOPSLA 2015）：一等"名字"做 nominal memoization，程序员控制复用粒度，实测比 Adapton 和全量重算都有大幅加速（具体倍数随负载，原文有 benchmark，未核实具体数字）。
5. **Salsa / rustc 红绿算法**（rust-analyzer、Ruff、Turbopack 在用）：全局 revision 计数器 + 每查询记录 last_changed/last_verified revision；重执行后若输出未变则 backdate（标绿），阻断级联失效。**工业界最成熟的可抄方案。**
6. **Jane Street Incremental**（OCaml 生产级）：v0.17 文档硬数字——每节点 ~216 字节、触发 50–150ns；配套 cutoff（phys_equal/set_cutoff）控制传播。

## 二、可直接抄
1. **失效判定用 revision 号而非全图重染**：Salsa 每结果存 R_changed/R_verified 两个整数，检查 O(1) → 我们的"状态层快照"应升级为"每个 modifier 存 (参数指纹, 输出 hash, revision)"，而不是整场景快照。
2. **backdating 截断级联**：重执行后发现输出与上次相同 → 标绿，下游不失效 → L3"重推下游"应改为"重推+比对，结果不变即停"，避免语义未变也重推。
3. **durability 分层**（rustc）：基础 mesh/材质/静态资源标高耐久，AI 迭代参数标低。
4. **restat 机制**（Ninja）：命令重跑后 re-stat 输出，mtime 未变就不向下游传播失效 → 等价于"modifier 重算后输出 hash 未变则不触发下游"，构建系统级成熟做法。
5. **参数离散化保缓存命中**（CADbuildr）：连续 float 是缓存杀手，滑块按视觉可分辨步长离散化；mesh 按 content-hash 复用。

## 三、坑 / 反直觉
1. **增量化没有免费午餐**：Jane Street 官方警告——incrementalization 降低更新代价但抬高从零重算代价和内存，"不要 incrementalize 一切"；节点数按 O(N) 膨胀（~216B/节点）。rust-analyzer 100K LOC 规模下查询缓存 200–400MB + 依赖图 100–200MB（第三方分析，未在官方文档核实）。
2. **"改了但结果没变"必须执行一次才能发现**（backdating 的代价）；hash/cutoff 设计直接决定收益；返回整值包装会 defeat cutoff（Jane Street 反模式）。
3. **异常会炸掉整个增量世界**：Jane Street stabilize 期间用户函数抛异常后系统永久不可用 → 编译/重推函数必须纯函数化、可重入。
4. **持久化依赖图会积累过时边**（Ninja deps log 的 stale edges，Fuchsia 承认无法检测，只能 clean build）→ 改"编译器本身"后旧指纹必须整体作废。
5. Acar 的 O(1) 追踪开销是摊还意义，常数因子不小（GC、对象分配）——Adapton 换 Rust 的动机之一就是 GC。

## 四、对本项目（关键回答）
**(a) 理论支持吗？支持，但切分粒度受 Blender 黑盒限制。**
自调整计算要求依赖可追踪，而 Blender GN 求值对 Python 是黑盒，GN 内部节点级脏标记不暴露（未核实 Blender depsgraph 是否可利用）。
→ **最小失效单位应定在 modifier（= opinion 层）**，不是 GN 内部节点、更不是参数：
每个 modifier 编译为 Salsa 式 tracked query，输入=具名参数集，输出=GN 结果 hash。
参数→modifier 的依赖边由我们的编译器**静态生成**（我们本来就产出显式 DAG）——比 Salsa 运行时动态追踪还便宜，这是相对通用增量系统的天然优势。

**(b) 成本拐点**：无几何领域公开实测（未核实）。经验锚点：Jane Street 单节点维护 ~216B + 50–150ns/次触发 → 依赖图维护比一次 GN modifier 求值（毫秒级）便宜 4 个数量级以上，维护成本几乎不会成为瓶颈；真正拐点在**失效比例**——rust-analyzer 1% 改动时增量 1.2s vs 全量 12–20s（10–20× 收益），但改动波及大部分图时优势消失且内存代价还在。
建议：失效 modifier 数 > 总数约 40%（经验阈值，需自测标定）时直接放弃增量走全量。

三条落地：
1. **三层回退映射**：L1=失效标记、L2=snapshot memoization、L3=change propagation——我们的架构与 SAC 理论惊人同构，缺的只是红绿算法的 **backdating** 和 **revision 判定**，补上即可把 L3 从"重推下游"变成"重推+比对+截断"。
2. 输出 hash 粒度：modifier 输出 mesh 用 LOD 降采样顶点做（近似）指纹，避免全 mesh hash 本身成为瓶颈（未核实有现成实现）。
3. 立刻可做实验：实测"重算单个 modifier + hash 比对"耗时 vs L3 的 50ms，确定按 modifier 切分是否已把收益吃满。
